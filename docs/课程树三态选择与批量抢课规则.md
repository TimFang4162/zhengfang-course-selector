# 课程树三态选择与批量抢课规则

## 目标

- 抢课任务的稳定对象只允许是"课程"和"教学班"。
- 大类不再是规则实体，只是对当前已加载课程列表的批量操作入口。
- 抢课任务不依赖用户当时使用的查询参数，不要求后端重新按大类推导课程集合。
- 后端只需针对用户显式给出的课程集合扫描教学班，再应用表达式过滤。

## 核心原则

1. 规则实体只有两种：`course` 和 `class`。
2. 大类勾选不生成 `category` 规则。
3. 大类勾选等价于：将该大类当前已加载的全部课程逐门设为选中。
4. 最终任务上下文只包含课程 / 教学班的包含与排除规则。

## 三态定义

课程和教学班节点都支持三态：

- `include`：显式纳入抢课范围。
- `exclude`：显式排除出抢课范围。
- `inherit`：自身不表态，跟随父节点。

其中：

- 课程节点的父级不是规则实体，因此课程的 `inherit` 等价于"未选中"。
- 教学班节点的父级是课程，因此教学班可以继承课程是否被纳入。

## 视觉状态

- 实心勾：显式 `include`
- 半透明勾：`inherit` 且父课程已 `include`
- 空框：`inherit` 且父课程未 `include`
- 排除态：显式 `exclude`

## 大类的语义

大类不存储规则，只根据其下当前已加载课程的状态聚合显示。

### 大类点击行为

- 若当前大类下课程未全选：点击后，将当前已加载课程全部设为 `include`
- 若当前大类下课程已全选：点击后，将当前已加载课程全部设为 `exclude`
- 若当前大类下课程当前均为 `exclude`：点击后，恢复为 `inherit`

大类显示的是一个聚合视图，不是独立规则项。

## 课程与教学班的语义

### 课程

- `include`：该课程的全部教学班都属于候选范围，除非某些教学班显式 `exclude`
- `exclude`：该课程整体排除，除非某些教学班显式 `include`

### 教学班

- `include`：该教学班属于候选范围
- `exclude`：该教学班不属于候选范围

教学班总是比课程更精确。

## 命中优先级

对于任意一个教学班，最终是否属于候选范围，按最精确规则决定：

1. 若命中教学班规则，则教学班规则优先
2. 否则看课程规则
3. 若都没有命中，则视为未选中

因此：

- `course exclude + class include`：该教学班重新纳入
- `course include + class exclude`：该教学班被排除

## 规则导出

最终导出结构只包含：

```json
{
  "includes": [
    { "type": "course", "categoryId": "1", "kchId": "000000X111A107" },
    { "type": "class", "categoryId": "1", "kchId": "000000X111A108", "classNo": "02" }
  ],
  "excludes": [
    { "type": "class", "categoryId": "1", "kchId": "000000X111A107", "classNo": "03" }
  ]
}
```

以下这种 `category` 规则实体不再允许进入任务系统：

```json
{ "type": "category", ... }
```

## 表达式生成

表达式中不再出现裸的：

```python
course.categoryId == "1"
```

每个正向条件都必须明确落到某门课程或某个教学班。

### 选中若干课程

```python
(
  (course.categoryId == "1" and course.id == "000000X111A107") or
  (course.categoryId == "1" and course.id == "000000X111A108") or
  (course.categoryId == "1" and course.id == "000000X111A109")
) and has_capacity and not conflicts
```

### 课程级选中 + 教学班级排除

```python
(
  (course.categoryId == "1" and course.id == "000000X111A107") or
  (course.categoryId == "1" and course.id == "000000X111A108")
) and not (
  (course.categoryId == "1" and course.id == "000000X111A107" and class.no == "03")
) and has_capacity and not conflicts
```

## 后端处理要求

后端接收 `selection` 时：

1. 只从 `includes` 中提取课程集合
2. 对这些课程逐门扫描教学班
3. 对每个教学班按"教学班规则优先，课程规则次之"判定是否属于候选
4. 最后再应用表达式过滤

后端不再：

- 根据 `category` 规则重新枚举课程
- 重新依赖用户当时的查询参数
- 允许 `category` 作为规则实体进入任务系统

## 限制与提示

- 大类批量操作只作用于"当前已加载课程"
- 若该大类仍有未加载分页，则未加载课程不会自动进入任务
- 用户若需要完整大类课程集合，应先加载完整课程列表，再执行大类批量选择

## 保留行为

- 原有单节点 `⋯ -> 添加抢课任务` 仍保留
- 新增的批量任务入口基于当前课程树选择规则工作
- 课程树中"已选"标签仍只表示课表状态，不参与抢课规则语义
