# 选课远程筛选接口与课程树重构规划

本文基于 `docs/webvpn.zjnu.edu.cn_2026_06_05_10_31_15.har` 和教务前端脚本分析整理，重点记录选课页面远程搜索、筛选字段生成逻辑，以及本项目课程树筛选功能的重构方向。

## 1. 证据范围

新 HAR 包含：

- `xsxk` 请求 16 条，覆盖选课页加载、课程列表、教学班明细。
- `xkgl` 请求 14 条，覆盖高级查询下拉数据源。
- `xtgl/comm_cxJcsjList` 请求 2 条，覆盖代码表类筛选项。

关键脚本来自 HAR 响应：

- `/js/plugins/searchbox/jquery.searchbox.contact-min.js`
- `/js/comp/jwglxt/xkgl/xsxk/zzxkYzb.js`
- `/js/comp/jwglxt/xkgl/xsxk/zzxkYzbZy.js`

## 2. 教务前端的筛选组件

选课页使用 `searchBox` 插件统一管理关键词和高级查询条件。

初始化入口在 `zzxkYzb.js`，核心配置类似：

```js
model: getConditionCols()
```

触发查询时，页面调用：

```js
var requestMap = $("#searchBox").searchBox("getConditions");
```

`searchBox` 的 `searchResult` 事件会调用页面提供的搜索回调。重置时会清空关键词、已选条件和内部 `conditionList`。

## 3. 关键词字段生成

`jquery.searchbox.contact-min.js` 中 `getConditions()` 处理关键词输入框：

```js
var D = $(b).find("div.buttons").find("input[name='searchInput']").val();
var F = [];
if ($.founded(D)) {
  $.each(D.split(" ") || [], function(G, H) {
    if ($.founded($.trim(H))) {
      F.push(H);
    }
  });
}
if (F.length > 0) {
  $.each(F, function(G, H) {
    E["filter_list[" + G + "]"] = H;
  });
}
```

结论：

- 关键词输入框字段名是 `searchInput`，但不会直接提交给业务接口。
- 前端按空格切分关键词。
- 每个非空关键词被转成 `filter_list[index]`。
- 单关键词样例：`filter_list[0]=马克思`。
- 多关键词理论形式：`filter_list[0]=foo&filter_list[1]=bar`。

如果存在搜索字段单选项，插件还会附加 `filterKey`，但本次 HAR 未观察到具体使用。

## 4. 高级筛选字段生成

高级查询字段由 `zzxkYzb.js` 的 `getConditionCols()` 动态生成。是否显示某个条件由隐藏开关控制，例如 `#zzxkgjcxkg_xy`、`#zzxkgjcxkg_zy` 等。

字段的统一规则是：

- 每个条件定义一个 `index`。
- 用户选择的值以 `index[n]=value` 形式进入 `requestMap`。
- 多选条件生成多个数组项。
- 父子联动由 `parent` 字段声明，例如专业依赖学院。

本次 HAR 直接确认的字段：

| 专业 | `zyh_id_list[0]` | `210` 或其他专业 ID | `/xkgl/common_queryZyPaged.html` |

### 5.2 推荐课表默认条件

`initCxtj(kklxdm)` 会根据课程类别操作 `tjbj_list_1`：

```js
if ($("#zzxkgjcxkg_tjbj").val() == "1") {
  if (kklxdm == "01") {
    $("li[index='tjbj_list_1']").find("a").click();
```

含义：

- 主修课程会默认选中推荐课表。
- 切换到非主修类别时会移除推荐课表条件。

本次 HAR 的主修课程请求中未出现 `tjbj_list[0]=1`，但出现了与推荐/规则相关的控制位：`zdkxms=1`、`sfkxq=0`。

## 8. 特殊观察：`zyh_id_list` 与 `jg_id_list`

本次 HAR 中，未筛选请求带：

```text
zyh_id_list[0]=210
```

筛选学院和关键词后，变为：

```text
jg_id_list[0]=45
filter_list[0]=马克思
```

同时 `zyh_id_list[0]` 不再出现。

但基础上下文字段仍保留：

```text
zyh_id=210
zyh_id_1=210
jg_id=45
```

推断：

- `zyh_id` / `zyh_id_1` 是页面上下文，定位当前学生所属专业。
- `zyh_id_list[n]` 是高级查询条件。
- 选择学院后，如果未选择具体专业，高级查询条件只提交 `jg_id_list[n]`，不提交 `zyh_id_list[n]`。

## 9. 本项目当前状态

当前 Web UI 的课程树搜索主要是本地筛选：

- `frontend/src/features/tree/search.js`：在已加载课程和教学班中做文本匹配。
- `frontend/src/App.jsx`：`远程搜索` 按钮只会展开并加载尚未加载的大类，没有把关键词传给教务端。
- `jwxt/web/server.py`：`/api/courses` 只接收 `category_id` 和 `page`。
- `jwxt/web/service.py`：`fetch_courses(category_id, page)` 只维护全量课程缓存。
- `jwxt/core.py`：`fetch_small_list(target, ..., page)` 只按类别和分页请求 `PartDisplay`。
- `jwxt/core.py`：`fetch_class_detail_and_plan(...)` 只按课程请求 `JxbWithKch`。

重要约束：

- 现有缓存 `course_info_cache[category_id][kch_id]` 代表“该大类已加载过的课程基础数据”。
- 如果直接把远程筛选结果写入现有全量缓存，会让课程树、导出、抢课预览误以为该大类只有筛选结果。
- 因此远程筛选结果必须和全量缓存区分，或者以只追加不覆盖的方式处理。

## 10. 课程树筛选重构目标

建议将课程树筛选拆成两层：

1. 本地视图筛选：只作用于已经加载到前端的课程树，不发教务请求。
2. 远程教务筛选：把关键词和高级条件传给教务端，返回匹配课程，再在树中展示。

用户可理解的行为：

- 输入关键词后按回车，默认执行本地筛选，响应最快。
- 点击远程搜索，按当前大类范围向教务端查询。
- 远程搜索结果应明确标注，例如“远程结果：主修课程 / 5 条”。
- 清空远程筛选后，回到普通课程树缓存。

## 11. 后端重构规划

### 11.1 筛选模型

新增一个内部筛选对象，先支持最小字段：

```json
{
  "keyword": "马克思",
  "collegeIds": ["45"],
  "majorIds": []
}
```

映射到教务字段：

```text
keyword tokens -> filter_list[0..n]
collegeIds -> jg_id_list[0..n]
majorIds -> zyh_id_list[0..n]
```

关键词拆分规则应匹配教务前端：按空格切分，忽略空片段。

### 11.2 core.py

扩展 `fetch_small_list`：

```python
def fetch_small_list(target, log_func, debug_func, page=1, remote_filters=None):
    data = {...}
    data.update(build_remote_filter_params(remote_filters))
```

扩展 `fetch_class_detail_and_plan`：

```python
def fetch_class_detail_and_plan(..., remote_filters=None):
    data = {...}
    data.update(build_remote_filter_params(remote_filters))
```

注意：教学班详情继承远程筛选是教务原页面行为，但本项目可先只在“远程结果模式”中传递，避免影响普通课程详情加载。

### 11.3 service.py

新增独立远程搜索接口，不复用普通 `fetch_courses` 的全量缓存语义：

```python
def search_courses(self, category_id: int, page: int, filters: dict):
    ...
```

缓存建议：

```text
course_search_cache[(category_id, filter_key)] = {
  "coursesById": {...},
  "loadedPages": [...],
  "hasMore": bool,
  "nextPage": int
}
```

`filter_key` 应使用规范化 JSON 生成，保证同一条件命中同一缓存。

普通课程树缓存仍保留：

```text
course_info_cache[category_id][kch_id]
```

搜索结果可以选择同步追加到普通缓存，但不能清空或覆盖普通缓存。

### 11.4 server.py

新增 POST 接口更合适，因为筛选条件含数组：

```text
POST /api/courses/search
```

请求体：

```json
{
  "categoryId": 0,
  "page": 1,
  "filters": {
    "keyword": "马克思",
    "collegeIds": ["45"],
    "majorIds": []
  }
}
```

返回体沿用 `/api/courses`：

```json
{
  "categoryId": 0,
  "page": 1,
  "count": 5,
  "hasMore": false,
  "nextPage": 2,
  "courses": []
}
```

可选新增：

```text
GET /api/course-filter-options?type=college&page=1&parentCollegeId=45
```

用于远程加载学院/专业筛选项。第一阶段也可以暂不做，只支持手填/内置当前学院。

## 12. 前端重构规划

### 12.1 状态拆分

建议将现有 `state.search` 拆成：

```js
search: {
  query: "",
  scope: "all",
  mode: "local", // local | remote
  remote: {
    active: false,
    loading: false,
    filters: {
      keyword: "",
      collegeIds: [],
      majorIds: []
    },
    results: {}
  }
}
```

`results` 按 `categoryId` 存储远程结果，避免污染 `categoryCourses`。

### 12.2 UI 行为

第一阶段建议保持 UI 简单：

- 搜索框：继续使用当前输入框。
- 范围：继续使用当前大类 scope。
- 按钮：保留“本地搜索”和“远程搜索”。
- 远程结果激活时显示 chip：`远程: 马克思`。
- 增加“清除远程结果”按钮或在清空关键词时自动退出远程模式。

高级筛选第一阶段只做学院/专业可以太重，建议先支持：

- 关键词 `filter_list`。
- 可选当前学院筛选 `jg_id_list`，如果已有用户学院上下文可默认使用。

第二阶段再加学院/专业下拉，并接入 `common_queryXyPaged` / `common_queryZyPaged`。

### 12.3 TreeView 数据源

`TreeView` 当前读取：

```js
state.categoryCourses[categoryId]
```

重构后应通过选择器函数读取：

```js
getVisibleCourseBucket(categoryId)
```

逻辑：

- 如果远程模式 active，优先返回 `state.search.remote.results[categoryId]`。
- 否则返回 `state.categoryCourses[categoryId]`。

这样可以减少 TreeView 直接理解搜索模式。

### 12.4 教学班加载

远程搜索结果中的课程点击展开教学班时有两种策略：

1. 继承远程筛选条件，完全模拟教务页面。
2. 不继承筛选条件，只按 `kch_id` 拉完整教学班。

建议第一阶段采用策略 2：

- 用户看到课程后，展开时应看到该课程完整教学班，便于抢课和选择。
- 避免 `filter_list` 对教学班详情造成不可预期过滤。

如果未来需要严格模拟教务页面，可在远程模式下给 `/api/classes` 增加 `filterKey` 或 `remoteFilters`。

## 14. 风险点

1. `filter_list` 的匹配范围由后端决定，可能不仅匹配课程名，也可能匹配课程号、教师或教学班名。
2. `filter_list` 多关键词是“与”还是“或”，本次 HAR 未覆盖，需要二次验证。
3. 高级筛选字段依赖页面隐藏开关，某些学校/批次可能不显示或不生效。
4. 远程筛选结果不要覆盖全量课程缓存，否则会影响导出、抢课预览、任务扫描。
5. 当前项目 `xklc` 硬编码和最新 HAR 中的 `xklc=2` 不完全一致，后续如重构请求参数，应优先从类别页隐藏字段解析。
